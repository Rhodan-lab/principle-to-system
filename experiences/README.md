# Learning Experiences

The core modules explain scientific and engineering ideas. The experience layer asks learners to *use* those ideas in situations where the answer is not given in advance.

Every experience follows a second arc:

```text
notice a system
→ choose a boundary
→ identify flows and state variables
→ propose a mechanism
→ build the smallest useful model
→ test the model against evidence
→ redesign the system
→ explain the remaining uncertainty
```

## Four experience families

| Folder | Purpose | Typical output |
| --- | --- | --- |
| [`system-dossiers/`](../system-dossiers/) | Reverse-engineer a familiar technology from physical principles upward | A layered architecture and principle-to-system chain |
| [`failure-atlas/`](../failure-atlas/) | Study how systems fail through interacting causes rather than isolated mistakes | A causal failure map and prevention strategy |
| [`investigations/`](../investigations/) | Explore an observable question with safe measurements, estimates, or simulations | An evidence notebook and revised explanation |
| [`design-challenges/`](../design-challenges/) | Design under explicit constraints without pretending there is one perfect solution | A trade-off table, model, and design rationale |

## Rules for all experiences

1. Begin with an observable phenomenon or concrete system.
2. State the system boundary and what is outside it.
3. Separate facts, assumptions, estimates, and design choices.
4. Include at least one quantitative model, even if it is deliberately simple.
5. Identify failure modes and trade-offs.
6. Avoid hidden scoring, competitive ranking, or artificial completion streaks.
7. Keep all physical activities safe, low-energy, and optional.
8. End with unresolved questions rather than a false sense of certainty.

## Suggested route

Start with the refrigerator dossier, continue to the feedback-instability failure pattern, run the room-cooling investigation, and then attempt the passive-cooler design challenge. Together they show the same thermodynamic system from four perspectives: explanation, failure, evidence, and design.
