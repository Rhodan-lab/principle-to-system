# System Dossiers

A system dossier reverse-engineers one technology across levels of explanation. It shows why each component exists, what flows through it, which models predict its behaviour, and what prevents the system from being ideal.

## Required structure

1. Observable system
2. System boundary and environment
3. Inputs, outputs, stores, and flows
4. Scientific principles
5. Components and functions
6. Interaction architecture
7. Quantitative model
8. Control and feedback
9. Failure modes
10. Efficiency and performance
11. Lifecycle consequences
12. Alternative designs
13. Principle-to-system chain
14. Unresolved questions
15. Sources and module links

Use [`templates/system-dossier.md`](../templates/system-dossier.md) for new dossiers.
