# System Dossiers

A system dossier reverse-engineers one technology across multiple levels of explanation. It must not stop at naming components. It should show why each component exists, what flows through it, what model predicts its behaviour, and what prevents the system from being ideal.

## Required structure

1. The observable system
2. System boundary and environment
3. Inputs, outputs, stores, and flows
4. Scientific principles used
5. Components and their functions
6. Interaction architecture
7. Mathematical model
8. Control and feedback
9. Failure modes
10. Efficiency and performance
11. Lifecycle and environmental consequences
12. Alternative designs
13. Principle-to-system chain
14. Questions the dossier does not yet answer
15. Sources and module links

## Quality test

A dossier succeeds when a learner could remove one component from the architecture and predict the consequences—not merely repeat the component's name.
