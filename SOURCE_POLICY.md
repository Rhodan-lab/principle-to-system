# Source Policy

Principle to System is only useful if every claim can be traced to a credible source. This policy governs how sources are selected, used, and recorded.

## Source hierarchy

Prefer sources in this order:

1. Primary scientific literature
2. Major review papers
3. Scientific consensus reports (e.g. IPCC, National Academies)
4. Standards organisations (e.g. BIPM, ISO, IEEE, NIST)
5. Government scientific agencies (e.g. NASA, NOAA, ESA, USGS)
6. Universities and research institutions
7. Recognised scientific and engineering societies
8. Peer-reviewed open textbooks (e.g. OpenStax)

## Rules

- Synthesise in your own words. Do not copy source language beyond brief, clearly attributed quotations.
- Inspect the actual source before citing it. Never cite from a search-result snippet alone.
- Never fabricate authors, titles, publication dates, DOI values, URLs, quotations, standards, measurements, equations, or experiment results. If a detail cannot be verified, omit it.
- Target approximately four to eight strong sources per module, adjusted to the breadth and complexity of the subject.
- Cite inline or in end-of-section reference lists within the learning files themselves. Do not create separate `evidence.md` files, claim IDs, confidence percentages, or claim-to-source matrices unless a genuinely disputed topic requires a brief clarification.

## The source ledger

Every source used anywhere in the repository must also be recorded in the central ledger at [`sources/source-ledger.md`](sources/source-ledger.md), with:

- source title;
- author or institution;
- date;
- URL or DOI;
- source type (using the hierarchy categories above);
- modules using the source;
- access date;
- a brief relevance note.

Update the ledger progressively as content is written, not retrospectively.
