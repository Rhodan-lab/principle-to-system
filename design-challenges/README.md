# Design Challenges

Design challenges ask learners to create a defensible system under constraints. They are not competitions and do not assume one best answer.

## Design cycle

```text
need
→ stakeholders
→ measurable requirements
→ constraints
→ concept alternatives
→ minimum model
→ trade-off comparison
→ failure analysis
→ selected design
→ test plan
→ redesign
```

## Required sections

1. Need and context
2. Stakeholders
3. Requirements and success measures
4. Hard constraints
5. Assumptions
6. System boundary
7. At least three concepts
8. Quantitative model
9. Trade-off matrix
10. Failure modes and safeguards
11. Test plan
12. Selected concept and rationale
13. What evidence could change the decision
14. Relevant modules and sources

## Design principles

- Requirements must be measurable where possible.
- Constraints are part of the problem, not obstacles to ignore.
- Every design moves risk rather than eliminating it completely.
- Simpler systems are preferred when they meet the same need reliably.
- A design rationale is stronger than an attractive sketch.
- Learners should state which values—cost, safety, repairability, efficiency, accessibility, or environmental impact—drive the decision.

## Initial challenge

- [Design a passive cooler](passive-cooler.md): preserve a cool interior without active refrigeration, dangerous materials, or hidden energy inputs.
